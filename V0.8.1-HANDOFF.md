# v0.8.1 — release state (2026-08-30)

Released. Every failure class reported against v0.8.0 is fixed and verified on
the packaged build, and three further defects were found by running the real
product rather than by reading it.

## Verification

- Orchestrator: **262 files, 2,873 passed**, 5 skipped
- CLI: **86 files, 872 passed**
- `pnpm check`, repository validation, and all 28 package/installer contracts pass
- Real gauntlet on the packaged build (`gpt-5.6-terra` via OpenAI): built a
  327-line regular-expression engine from scratch — parser, Thompson NFA
  compiler, simulator — with **10/10 tests passing independently**, the
  pathological `(a+)+b` case completing in 25 ms, and **no use of the host
  regex anywhere**. 5/5 failures recovered, 0 human interventions, 6m51s.

## Found by running it, not by reading it

Three defects that no unit test would have caught, each fixed and covered:

1. **Unattended delegation hang.** `ask_teammate` created an approval nothing
   could answer inside a `morrow build` run; the mission sat until its
   35-minute timeout. Not offered to mission workers now, and refused fast if
   reached.
2. **Continuation cut off after one prose reply.** A run answered its first
   directive with prose and was stopped four seconds later having delivered
   only `.gitignore`. A task that has produced nothing now gets a second
   attempt; one with work to stop on still stops after one.
3. **Directives asked for verification of things that did not exist.** A
   workspace holding only `.gitignore` was told `frontend_route_missing` was
   outstanding, and spent both continuations opening a browser on an empty
   directory. Delivery is now named alone; verification follows delivery.

The third is why the final run built anything at all.

## Known limitation, carried forward from 0.8.0

**Mission mode can report `blocked` on correct work.** The final gauntlet built
a working engine whose tests pass, and the mission still graded it `blocked`.
The reason is in its own words: *"The truncated implementation prevents complete
review"*, and *"index.js and test/ reported as changes outside the engine
implementation scope"*. The reviewer could not see the file it was judging.

This is an **evidence-capture** problem, not a missing continuation. An earlier
diagnosis in this project claimed the mission layer "stops instead of
continuing" and proposed applying `continuation-policy.ts` one layer up. That
was wrong: `controller.ts:180-189` already goes `recovering → replanning` and
re-dispatches, bounded by `recovery.exhausted`, and `guardian.ts:197-204` gates
on review-cycle budgets. The mission layer continues; it exhausts its budget
because criteria can never be verified from lossy evidence.

**The next piece of work** is therefore: make verification evidence complete
enough for the reviewer to judge — untruncated implementation inspection, and
correct change-set scoping so delivered files are not reported as outside the
mission's scope. Fix that before adding any further mission machinery.

Agent-level behaviour is sound: `morrow yolo` completed a comparable task
(cronwhen, 20/20 tests) end to end without prompting.
